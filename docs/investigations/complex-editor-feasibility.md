# D-03 — Google Docs and complex-editor feasibility

Decision (revised 2026-10-02 at the owner's request): **no replacement and no checks of any kind in Google Docs; canvas, closed and opaque surfaces use the user-pasted text in the manual panel; rich contenteditable editors in five verified families (Draft.js, Lexical, Slate, ProseMirror, Quill) get an in-place Accept; every other rich editor stays copy-only.** The earlier rule that no recognized complex editor could be written to is replaced for those five families only, and only through the editor's own input pipeline (see the [inline guide](../implementation/inline-mvp.md#rich-editor-inline-checking)); Lineleaf never writes DOM nodes and uses no private editor API. Gmail, LinkedIn, Slack and Notion composers, whatever their internals, remain opt-in copy-only until an authenticated draft-only check passes. No working Google Docs, Notion, or framework-specific adapter is advertised. This is a feasibility decision plus a locally verified delivery path, not live editor support.

## Findings and decision

| Surface/model | Source-backed observation | Consequence for Lineleaf |
| --- | --- | --- |
| Google Docs | Google announced canvas rendering and warned that extensions depending on HTML could need changes; its supported integration direction is Workspace add-ons/APIs | DOM text nodes, hidden input proxies and selection offsets are not evidence of a document mutation/undo API. Guard the whole `docs.google.com` host against replacement and automatic checks. Do not scrape canvas, accessibility mirrors, clipboard contents or whole documents. |
| Lexical | Its official documentation identifies editor state, rather than the DOM, as the source of truth; updates run through editor operations | A DOM write would not be a model transaction, so Lineleaf does not write the DOM. It delivers the edit as an ordinary input event, which Lexical turns into its own update and history entry: with Lexical 0.52 the model and DOM agreed after the edit and its own undo restored the text. No private Lexical API is used. Locally verified only; see the gate below. |
| ProseMirror | Its official guide describes state, transactions and a view that renders the model to the DOM | A successful DOM insertion alone is insufficient proof, so the model is compared with the DOM in the verification runs. With ProseMirror view 1.42 the editor reconciled the native edit into a transaction, the document matched and its own history undid it. |
| Slate, Quill, Draft-style markers | A native `insertText` alone is not safe everywhere: with Slate 0.126/slate-react 0.127 it changed the DOM but not Slate's model, so the next render could discard it | The manual panel still guards `[data-slate-editor]`, `.ql-editor`, `.DraftEditor-root` and `.public-DraftEditor-content` (including ancestor/descendant markers). The inline Accept first offers the edit as a cancelable `beforeinput`, which Slate takes itself; Draft.js 0.11.7 and Quill 2.0.3 reconcile the native edit and kept model, DOM and their own undo consistent. These are separate, uncommitted local runs of the real libraries in headless Chromium. |
| Notion and priority rich composers | No dedicated, tested application adapter exists in Lineleaf | Known Notion hosts and Gmail/LinkedIn/Slack rich contenteditable use copy fallback (and the same opt-in copy-only inline preview) even when a framework marker is present. No claim is made about their current internal editor libraries. |
| Monaco/CodeMirror, closed roots and opaque/cross-origin frames | These are outside the product's accepted writing/editor scope | Code regions are excluded; inaccessible roots/frames are not traversed. The manual pasted-text path is available on an enabled, eligible HTTP(S) page. |

Sources reviewed 2026-10-02:

- [Google Workspace: Docs canvas rendering](https://workspaceupdates.googleblog.com/2021/05/Google-Docs-Canvas-Based-Rendering-Update.html). This 2021 announcement explains an architectural obstacle; it is not a fresh inspection of today's signed-in Docs UI.
- [Lexical editor state](https://lexical.dev/docs/concepts/editor-state).
- [ProseMirror guide](https://prosemirror.net/docs/guide/).
- [Chrome content script frame permissions](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) and [scripting document targets](https://developer.chrome.com/docs/extensions/reference/api/scripting).

The consequences above are Lineleaf engineering decisions inferred from those model boundaries and the absence of a verified adapter.

## Working fallback

Open Lineleaf on an enabled eligible page. If the surface exposes a bounded ordinary DOM selection, check it explicitly and copy the result. Otherwise copy text yourself, paste up to 2,000 characters into the panel, select **Use pasted text**, choose proofreading or a rewrite and press **Check selection**. Suggestions remain copy-only; the user controls paste and the editor's own undo. Typing in the paste field alone makes no provider call. Editing it invalidates a checked snapshot; close, navigation, pause, policy changes and expiry clear the captured text. There is no background clipboard read or persisted draft.

The [compatibility suite](../../tests/compatibility.test.mjs) verifies the Google Docs input-proxy guard, the pasted-text path, complex markers even with flat inline DOM, denied clipboard/manual copy, and source/format preservation. This is synthetic evidence; a live Docs/Notion round trip is not claimed.

## Gate for direct replacement

A separate implementation needs an identifiable, versioned editor interface and permission boundary; explicit selected-text extraction with model positions; revision/transaction identity and exact-source rechecks; a native model transaction preserving formatting, names/numbers, selection and collaboration state; and editor-owned undo that cannot overwrite other users' or later local edits. Test the actual application and supported versions on the advertised browser/OS, including IME, history, rerenders, removal/navigation and concurrent/collaborative edits. Keep preview/copy when any gate fails. Undocumented private globals, forcing an alternative Docs renderer, or injecting text into a hidden proxy do not satisfy these gates.

Where the five families stand (2026-10-02): the versions above are identified by library markers and tested locally; the exact paragraph text and positions are checked at the current revision before the edit, after it and again 250 ms later; the edit enters through the editor's own input pipeline, so its transaction, selection and undo are the editor's; a change across a formatting or mention boundary is not attempted; and a mismatch makes the editor copy-only. **Not yet met:** real application builds (X's customized Draft.js, Gmail, LinkedIn, Slack, Notion), IME in these editors, and concurrent or collaborative editing. Those composers therefore stay behind the host guard or, for X, remain a live acceptance item (D-03 stays IMPLEMENTED — VERIFY).
